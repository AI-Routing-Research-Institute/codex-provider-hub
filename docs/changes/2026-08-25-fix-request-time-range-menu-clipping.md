# 修复请求页时间范围弹层显示

## 目标

确保请求页时间范围选择弹层在筛选栏窄列中完整显示，不被视口边界或相邻筛选项遮挡。

## 现状

共享时间范围弹层固定为 320px 并右对齐于 176px 的请求页筛选列，窄窗口下可能向左超出视口，造成内容显示不全。

## 设计范围

- 根据触发控件和视口空间，在相对定位容器内选择左对齐或右对齐。
- 弹层宽度限制为 `min(320px, 视口宽度 - 24px)`。
- 打开时提升选择器层级，确保弹层覆盖相邻筛选项。

## 非目标

- 不修改时间范围种类、日期精度、接口参数或应用流程。
- 不调整其他请求页筛选项和表格布局。

## 兼容性

无接口、配置或数据影响，仅修复弹层定位和可见性。

## 风险

定位逻辑仅影响弹层展示；视口空间不足时缩小弹层宽度，保证内容仍在可视区域内。

## 测试计划

- 更新 Vue UI 契约测试，断言视口宽度限制、相对定位和对齐逻辑。
- 运行全部 Node 测试、前端构建和 `git diff --check`。
- 在请求页窄窗口和正常桌面窗口检查弹层完整显示。

## 实际改动

- `TimeRangeSelect.vue` 根据触发控件与视口空间选择左右对齐，并在窗口变化时重新计算。
- `styles.css` 限制弹层最大宽度、提升打开层级并保留 6px 相对定位。
- `tests/local_proxy_vue_ui.test.js` 增加视口宽度与对齐样式契约断言。

## 验证结果

- `node --test $testFiles`：16 项通过。
- `npm run build`：Vite 生产构建通过。
- `node --check proxy_static/src/timeRange.js`、`api.js`、`ccswitch.js`：通过。
- `git diff --check`（本次源码、测试和说明文件）：通过。
- 浏览器实测：默认 1280px 视口下弹层右对齐并贴合触发按钮；440px 视口下自动左对齐，弹层范围为 `12..332`，完整位于视口内。

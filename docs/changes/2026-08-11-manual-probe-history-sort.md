# 按手动检测历史排序供应商

## 目标

让公开状态页对手动-only 供应商使用目标模型的最近手动成功时间排序，和自动检测供应商使用最近自动成功时间的规则保持一致。

## 现状

手动-only 供应商不会生成自动检测模型记录。上一版排序修复只读取最新手动检测任务；如果最新一次手动检测失败，但更早的手动历史中存在目标模型成功记录，供应商仍会被当作没有成功记录排在末尾。

## 设计范围

- 公开状态接口在排序前读取最新手动任务和手动检测历史。
- 目标模型缺少自动检测记录时，从最新手动任务和手动历史中寻找最近成功结果。
- 最新手动检测失败但历史中存在更早成功时，按最近成功时间参与排序。
- 手动历史中没有目标模型成功结果时，继续使用缺失模型兜底顺序。
- 同步公开状态接口和排序函数测试。

## 非目标

- 不改变手动检测任务执行、记录保存或页面展示文案。
- 不改变自动检测供应商已有排序优先级。
- 不调整整体状态聚合规则。
- 不修改数据库结构或配置。

## 兼容性

接口字段、配置和数据库结构不变；仅调整公开状态接口返回的供应商顺序。属于向后兼容缺陷修复，版本选择 `patch`。

## 风险

- 手动历史仅保留有限条数；超过历史保留范围的成功记录不会参与排序。
- 历史时间异常可能导致错误排序；无法解析的时间会被忽略并回到兜底顺序。
- 手动-only 供应商状态仍可能显示 `unknown`；本次只让排序逻辑与“最近成功”规则一致。

## 测试计划

- 测试最新手动任务失败但手动历史存在目标模型成功时，手动-only 供应商排在无成功记录的自动失败供应商之前。
- 测试手动历史里其他模型成功不会提升目标模型排序。
- 测试自动检测已有目标模型成功时仍优先于手动历史成功。
- 运行状态页相关 Python 测试和完整回归。

## 实际改动

- `provider_status/web.py` 在公开状态接口排序前读取手动检测历史，并将最新任务与历史一起传入排序函数。
- 缺少自动检测目标模型记录时，排序函数会从最新手动任务和手动历史中寻找目标模型最近成功时间。
- 最新手动任务失败但历史中存在目标模型成功时，供应商会按最近成功时间排在没有成功记录的供应商之前。
- `tests/test_status_web.py` 增加接口级复现测试和排序函数边界测试，覆盖最新失败、历史成功和其他模型成功不误提升的情况。

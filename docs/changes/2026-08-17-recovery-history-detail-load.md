# 恢复记录详情加载

## 目标

让恢复记录弹层可靠加载完整分页数据，避免在详情请求尚未完成或暂时失败时长期只显示状态摘要中的一条记录。

## 现状

状态轮询为了控制响应体大小只返回最新一条恢复记录。弹层打开后异步请求 50 条详情，但首次请求期间仍渲染摘要；详情请求失败时错误被静默忽略，后续状态轮询也不会再次触发加载。

## 设计范围

- 首次加载详情期间显示明确的加载状态，不把摘要一条误标为已完成详情。
- 详情请求失败时保留已加载内容，并在弹层保持打开期间由受控重试恢复加载。
- 成功加载后继续支持现有分页滚动、摘要合并和滚动位置保持。
- 增加 JavaScript 行为测试覆盖首次加载、失败重试和已有详情不被覆盖。

## 非目标

- 不改变恢复记录数据库、统计窗口或服务端分页接口。
- 不改变自动恢复、重试策略或请求记录写入逻辑。
- 不增加新的用户操作页面或手工刷新按钮。

## 兼容性

仅改变控制台前端的恢复记录展示和请求调度；后端接口、SQLite 数据和已有历史记录格式保持兼容。版本提升选择 `patch`，因为这是现有功能的加载可靠性修复。

## 风险

- 网络或本地服务持续不可用时，自动重试不能保证立即成功，因此需要避免高频请求并保留当前内容。
- 状态摘要可能在详情请求期间更新，重试必须使用最新摘要判断是否需要继续加载。
- 弹层打开和关闭之间存在异步请求竞态，需要避免重复请求和覆盖较新的详情数据。

## 测试计划

- 覆盖首次详情请求触发、加载状态和请求成功后的详情渲染。
- 覆盖详情请求失败后在弹层保持打开时的受控重试。
- 覆盖已有完整详情在状态摘要刷新时不退化为一条记录。
- 运行完整 Python 单元测试、JavaScript 测试、JS 语法检查、`git diff --check` 和 UTF-8 解码检查。

## 实际改动

- 修改 `proxy_static/app.js`，区分状态摘要和已加载详情，并在首次补拉时显示明确的加载状态。
- 为详情请求失败增加 2 秒节流窗口；弹层保持打开且没有并发请求时，由状态轮询自动重试。
- 保留已有详情、分页游标和滚动位置，刷新失败不会退回状态接口的一条摘要。
- 扩展 `tests/local_proxy_recovery_history.test.js`，覆盖补拉判断、并发保护、重试节流和状态文案。

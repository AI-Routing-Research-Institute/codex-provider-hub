# 临时性 HTTP 400 错误继续重试

## 目标

让本地中转解析 HTTP 400 响应正文，只对模型繁忙、容量已满、渠道不足和上游暂时不可用等临时错误继续执行既有无限重试，同时让参数错误、上下文超长等永久错误立即返回客户端。

## 现状

本地中转当前只按状态码重试 `500`、`502`、`503`、`504` 和 `429`，任何 HTTP 400 都会直接透传。已观察到同一请求在 Any Router 返回 426 次“模型负载达到上限”后，最终收到 HTTP 400 并结束重试，Codex 客户端仅显示 `Provider run failed`。

## 设计范围

- 在向客户端提交任何 HTTP 400 输出前，限量读取并解析脱敏错误正文。
- 识别 JSON 与纯文本中的中英文临时错误语义，包括模型繁忙或容量已满、无可用渠道、上游暂时不可用和稍后重试提示。
- 复用现有模型容量、频率限制和上游错误分类，临时错误进入原有重试循环并遵循 `max_attempts = -1` 的无限重试设置。
- 对带有 `invalid_request_error`、`model_not_found`、权限、认证、额度、内容策略等永久错误代码的 HTTP 400 保持立即透传。
- 未识别的 HTTP 400 默认立即透传，并完整保留已经为分类读取的响应字节。
- 错误摘要继续经过现有脱敏和长度限制后写入恢复记录。

## 非目标

- 不将所有 HTTP 400 无条件视为可重试错误。
- 不改变无限重试、固定或指数退避配置。
- 不增加自动选择下一供应商的逻辑；重试期间手动切换供应商的现有行为保持不变。
- 不修改客户端、CC Switch 数据库、供应商配置或生产服务。
- 不自动重启当前本地中转实例。

## 兼容性

无接口、配置或数据库迁移。已有重试配置继续生效；仅临时性 HTTP 400 从“立即透传”改为“按现有策略重试”。属于向后兼容缺陷修复，版本选择 `patch`。

## 风险

- 文案匹配过宽可能让永久错误进入无限重试；永久错误代码优先于临时文案，并采用明确的中英文短语白名单。
- 为判断 HTTP 400 而读取正文可能改变透传内容；分类器限制读取大小，并在不重试时把已读取字节原样交还响应流。
- 错误正文可能包含凭据或请求标识；所有持久化摘要继续使用现有脱敏与长度限制，响应正文不新增持久化副本。
- 超大或格式异常的 HTTP 400 可能无法分类；超过读取上限或解析失败时保持原有立即透传行为。

## 测试计划

- 验证模型容量已满、无可用渠道和上游暂不可用的 JSON/纯文本 HTTP 400 会重试并在后续成功时返回成功响应。
- 验证 `invalid_request_error`、上下文或参数错误以及未知 HTTP 400 只请求一次并原样透传。
- 验证分块 HTTP 400 正文能够分类，永久错误的已缓冲字节不会丢失或重复。
- 验证恢复记录保存脱敏后的临时错误分类与摘要。
- 运行完整 Python、Node 测试、JavaScript 语法、Python compileall 和 diff 检查。

## 实际改动

- `local_proxy/core.py` 在 HTTP 400 响应向客户端输出前最多缓冲 4 KB 解码后正文，支持完整 JSON、顶层 `message/code/type`、嵌套 `error` 和纯文本错误分类。
- 临时错误白名单覆盖中英文模型繁忙或容量已满、无可用渠道、上游暂不可用和稍后重试提示，并复用现有 `model_capacity`、`upstream_error` 与脱敏摘要。
- 永久错误代码与无代码文案增加上下文超长、参数无效、请求过大和不支持字段等类别，并在临时文案匹配前优先返回，防止“请稍后重试”提示让永久错误进入无限重试。
- 未识别、永久、超大或读取较慢的 HTTP 400 将已缓冲字节和待完成分块无损交还响应流；分块正文不会丢失、截断或重复。
- HTTP 400 分类使用 HTTPX 解码后的正文，gzip 响应透传时移除 `Content-Encoding`，避免客户端对已解码正文再次解压。
- `tests/test_proxy_core.py` 增加嵌套 JSON、顶层 JSON、分块 JSON、纯文本、gzip、慢分块、4 KB 边界以及永久错误透传回归测试。

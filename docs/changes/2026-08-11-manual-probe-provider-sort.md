# 修正手动检测供应商排序

## 目标

让公开状态页在排序供应商卡片时识别手动检测结果，避免手动-only 供应商已检测可用却因为没有自动检测模型记录而排到列表末尾。

## 现状

状态页当前按固定模型 `gpt-5.6-sol` 的自动检测结果排序，只读取供应商 `models` 中的连续成功次数和最近成功时间。手动-only 供应商不会产生自动 `models` 记录，即使最近手动检测该模型成功，也会被当作缺少排序模型处理并排在最后。

## 设计范围

- 公开状态接口在排序前读取最新手动检测任务。
- 排序函数在目标模型缺少自动检测记录时，使用同供应商最新手动检测任务中的目标模型结果作为兜底信号。
- 手动检测成功按最近成功时间参与排序，排在没有成功记录或明确不可用的供应商之前。
- 自动检测已有目标模型记录时维持现有排序规则。
- 同步状态接口和排序单元测试。

## 非目标

- 不修改探测调度、手动检测按钮或检测任务执行逻辑。
- 不改变公开状态接口字段结构。
- 不引入新的供应商配置项或数据库迁移。
- 不调整整体状态聚合规则。

## 兼容性

接口、配置和数据库结构均保持兼容；仅调整公开状态接口的供应商排序。属于向后兼容缺陷修复，版本选择 `patch`。

## 风险

- 最新手动检测任务可能不包含排序模型；此时继续使用原有缺失模型兜底顺序。
- 手动检测失败不应优先于自动健康供应商；排序仅将成功手动结果作为最近成功信号，失败或排队结果不提升排名。
- 手动-only 供应商的 `state` 仍可能为 `unknown`；排序变化不改变状态文案，只改善卡片位置。

## 测试计划

- 测试手动-only 供应商在最新手动检测 `gpt-5.6-sol` 成功后，排在自动检测失败且无成功记录的供应商之前。
- 测试手动检测失败或缺少目标模型时不提升排名。
- 测试排序函数继续保持自动检测连续成功和最近成功优先规则。
- 运行状态页相关 Python 测试和仓库必要静态检查。

## 实际改动

- `provider_status/web.py` 在公开状态接口排序前读取最新手动检测任务，并将其传入供应商排序函数。
- `_sort_providers_by_model` 在目标模型没有自动检测记录时，使用同供应商最新手动检测任务中的成功结果作为最近成功信号。
- 手动检测失败、模型不匹配或完成时间无效时继续沿用原有兜底顺序，不提升排名。
- `tests/test_status_web.py` 增加公开状态接口复现测试和排序函数边界测试，覆盖手动-only 供应商成功、失败和目标模型缺失场景。

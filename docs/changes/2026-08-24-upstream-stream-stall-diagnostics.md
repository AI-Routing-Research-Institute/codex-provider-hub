# 上游流式请求卡顿保护

## 目标

防止上游 Responses/SSE 连接建立后长时间无数据，导致本地中转请求、控制页面和状态展示长期停留在等待状态；让卡顿请求能够被识别、收尾并留下可诊断的信息。

## 现状

本地 Codex 上游 HTTP 客户端使用 `read=None`，流式响应只要连接未主动断开就会无限等待。当前控制页面请求也没有浏览器侧超时，无法区分服务无响应和单个请求仍在等待上游。现有 SQLite 异步化修复已经避免数据库查询和写入直接阻塞 ASGI 事件循环，但没有覆盖上游静默流。

## 设计范围

- 为上游流式响应增加按数据块计算的空闲读取超时，不改变请求总时长限制。
- 首个输出前发生空闲超时时，按现有可重试错误流程处理；输出已经开始后只关闭当前流并记录明确的流级失败，不重放已输出内容。
- 保证超时、客户端断开和正常结束都会关闭上游响应、释放路由活动计数并异步写入请求记录。
- 在健康状态和运行中请求信息中提供请求年龄/阶段等诊断字段，帮助区分上游等待和服务本身无响应。
- 为本地控制台状态、请求记录和相关读取增加浏览器侧请求超时，避免页面永久保留 pending 请求。
- 保留用户现有的无限重试设置，不在本次修改中改变 `max_attempts` 或重试间隔配置。

## 非目标

- 不修改用户当前的无限重试配置、重试次数或重试策略。
- 不改变供应商选择、会话路由、供应商凭据和远程状态服务配置。
- 不在已经开始输出响应后重放请求。
- 不引入全局代理、供应商网络代理或新的上游传输协议。

## 兼容性

新增字段仅用于本地健康和控制接口，旧客户端可以忽略。现有请求记录数据库无需重建，新增行为只在上游流连续静默达到阈值时生效。该改动为向后兼容的缺陷修复，版本 bump 选择 `patch`。

## 风险

上游长时间推理但暂时没有输出时，空闲阈值过短可能误判；因此使用按数据块计算的独立阈值，并保留连接建立、写入和连接池超时的原有设置。输出开始后的超时不能安全重放，只记录流级失败并释放资源。前端超时只影响控制页面请求，不会取消后端模型请求。

## 测试计划

- 测试上游流在空闲阈值内持续输出时可以正常完成。
- 测试首个输出前空闲超时会释放请求并进入可重试/失败收尾路径。
- 测试输出开始后空闲超时不会重放请求，且活动请求计数归零并保存失败记录。
- 测试健康状态和运行请求返回诊断字段。
- 测试前端控制请求超时、状态轮询恢复和错误展示。
- 运行相关 Python 单测、Node 测试、JavaScript 语法检查和 Python 编译检查。

## 实际改动

- `local_proxy/core.py`：为上游响应头和流式数据增加有界超时；首包前超时进入现有重试，输出后超时只收尾并记录，不重放已输出内容。
- `local_proxy/core.py`：将大请求体元数据解析、item ID 兼容转换、SSE/Token 捕获和最终估算移出 ASGI 事件循环，增加运行阶段、最近活动时间和事件循环延迟诊断。
- `local_proxy/server.py`：统一 Codex/Claude 服务的健康诊断、超时参数和活动请求阶段透传。
- `proxy_static/app.js`：为控制页面读取增加 8 秒请求超时，显示上游连接、等待首包、接收中和超时状态。
- `proxy_static/index.html`：更新页面脚本缓存版本。
- `tests/test_proxy_core.py`、`tests/test_server.py`、`tests/local_proxy_requests.test.js`：覆盖超时收尾、重试、活动计数、诊断字段和前端状态文案。

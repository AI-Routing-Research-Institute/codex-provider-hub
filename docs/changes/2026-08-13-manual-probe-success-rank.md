# 统一手动与自动成功排序

## 目标

公开状态页按目标模型的实际成功表现排序供应商，不再因为供应商使用点击检测而把最近成功结果降到所有自动检测成功记录之后。

## 现状

当前排序把自动检测连续成功、自动检测历史成功和点击检测成功分为三个等级。点击检测成功固定处于第三级，即使成功时间更新、其他自动供应商当前已不可用，也只能排在所有曾自动成功的供应商之后。线上佛爷 API 最近点击检测成功，因此仍被排到倒数第二。

## 设计范围

- 自动检测目标模型连续成功时继续优先，并按连续成功次数降序。
- 没有连续成功时，自动检测与点击检测的最近成功时间使用同一排序等级。
- 同一供应商同时存在自动与点击成功记录时使用两者中更新的时间。
- 从未成功或成功时间无效时保持配置原始顺序。
- 增加排序函数和公开状态接口回归测试。

## 非目标

- 不改变服务器 `providers.toml` 或状态库 `display_order`。
- 不改变自动检测调度、点击检测任务、状态聚合和页面文案。
- 不修改公开状态接口字段结构。

## 兼容性

无接口、配置或数据库迁移，仅调整公开状态接口中的供应商卡片顺序。版本选择 `patch`，因为这是已有点击检测排序语义的缺陷修复。

## 风险

最近一次成功会让点击检测供应商进入前列，即使它没有自动连续成功信号；连续自动成功仍保留最高优先级，降低单次点击成功超过稳定自动供应商的风险。

## 测试计划

- 测试点击检测最近成功排在较旧自动成功之前。
- 测试自动连续成功仍排在点击检测成功之前。
- 测试同一供应商使用自动与点击结果中的更新成功时间。
- 运行状态页测试、Python 和 JavaScript 全量测试、语法与 diff 检查。

## 实际改动

- `provider_status/web.py`：目标模型没有自动连续成功时，合并自动检测与点击检测的最近成功时间，并将两种成功来源放入同一排序等级；点击检测供应商不再被检测模式固定降级。
- `tests/test_status_web.py`：更新点击成功排序预期，增加与线上信号一致的稳定自动、近期点击、较早自动三方排序测试，以及同一供应商自动/点击结果取更新时间的测试。

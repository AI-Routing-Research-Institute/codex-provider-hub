# 时间筛选选项持久化与当天结束边界

## 目标

让 Token 统计和请求记录在刷新页面后保持用户最后选择的“今日、近 24 小时、近 7 天或自定义”等时间选项，并允许自定义结束时间选择到本地当天 `23:59:59`，使当天后续新增记录能够持续进入查询结果。

## 现状

应用自定义时间后，浏览器只保存起止时间，没有保存当前选中的时间类型。用户随后改选“今日”等预设时只更新内存状态；页面刷新后，旧自定义范围仍会被无条件恢复并重新激活。自定义弹层同时禁止结束时间晚于当前时刻，因此选择当天范围时，后续产生的新记录会落在固定结束时间之外。

## 设计范围

- 在现有按服务、按目标隔离的本地存储键中，同时保存当前时间选项和最近一次自定义范围。
- 选择任意固定预设时立即持久化该选项，但保留最近一次自定义范围供下次编辑。
- 页面刷新时仅在保存的选项确实为 `custom` 且范围有效时恢复自定义；否则恢复保存的固定预设。
- 兼容旧版本仅保存 `{start, end}` 的本地数据，并将其视为旧的自定义选择。
- “今日”预设继续使用从本地当天零点到当前时刻的动态查询，不设置固定结束时间。
- 自定义结束时间允许到本地当天 `23:59:59`；明天及更远的未来日期仍然拒绝。
- 请求记录继续遵守最近 7 天保留范围和最长 7 天自定义跨度。

## 非目标

- 不增加跨设备或服务端同步筛选偏好。
- 不改变数据库结构、记录保留周期或后端查询参数格式。
- 不允许选择明天或更远日期作为自定义结束时间。
- 不自动重启本地中转。

## 兼容性

无接口、配置或数据库迁移。现有本地存储键保持不变，并兼容旧的自定义范围结构；固定预设和自定义查询参数继续使用现有 API。属于向后兼容缺陷修复，版本选择 `patch`。

## 风险

- 存储结构升级可能导致旧范围丢失；恢复逻辑显式识别旧 `{start, end}` 结构并保留原行为。
- 放宽当天结束时间可能误允许未来日期；校验使用浏览器本地时区计算当天最后一毫秒，并继续拒绝超过该边界的值。
- 请求历史自定义范围可能跨过 7 天限制；现有跨度和保留边界校验继续在当天结束边界校验之后执行。
- 预设与自定义状态可能再次不一致；由单一恢复函数返回规范化的 `{window, range}`，并增加刷新恢复回归测试。

## 测试计划

- 验证保存过自定义范围后改选“今日”，重新加载仍恢复“今日”且保留范围供后续编辑。
- 验证旧 `{start, end}` 存储结构继续恢复为自定义。
- 验证当天 `23:59:59` 可用、明天零点不可用。
- 验证请求记录仍拒绝超过最近 7 天或跨度超过 7 天的范围。
- 运行完整 Python、Node 测试、JavaScript 语法、Python compileall 和 diff 检查。

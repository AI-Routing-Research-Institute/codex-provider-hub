# 自定义统计时间范围与七日请求记录

## 目标

为供应商 Token 统计和请求记录提供精确到秒的开始、结束时间筛选，并将请求记录保留周期从 24 小时延长到 7 天。

## 现状

供应商统计仅支持固定的今日、近 24 小时、近 7 天、近 30 天和全部范围；请求记录仅支持近 1、6、24 小时且超过 24 小时会被清理。用户无法定位任意起止秒内的 Token 与请求，也无法回看前几日请求。

## 设计范围

- 两处时间下拉框增加“自定义时间…”入口并复用同一弹层组件。
- 弹层使用独立日期与 `HH:mm:ss` 时间输入，支持取消、应用、外部关闭和 Escape。
- 供应商与请求页面分别保存自定义范围；应用后在页面说明中显示紧凑范围。
- 控制接口统一接受毫秒级 `start_at`、`end_at`，自定义范围包含所选结束秒。
- Token 汇总、供应商使用历史、请求记录及分页查询均执行同一时间边界。
- 请求历史保留周期延长为 7 天，并增加近 7 天预设；自定义请求范围限制在本地保留边界内。
- 固定预设、刷新、供应商切换和管理操作保持现有行为。

## 非目标

- 不恢复已经被旧版本清理的请求记录。
- 不改变 Token 使用记录的持久化周期。
- 不增加服务端时区配置或跨设备同步筛选偏好。

## 兼容性

接口新增可选查询参数，原有固定 `window`/`usage_window` 参数继续支持。数据库结构不变，仅将新产生请求的清理边界延长到 7 天；已有配置无需迁移。属于向后兼容功能增强，版本选择 `minor`。

## 风险

- 本地请求数据库会因保留 7 天而增长；继续在写入和读取时清理边界外记录，并依赖现有索引保证查询性能。
- 本地时间转换可能产生边界偏差；浏览器统一转为 Unix 毫秒，后端使用绝对时间并将结束秒转换为排他上界。
- 自定义范围分页若参数丢失会混入区间外记录；前端集中生成查询参数，后端所有列表和汇总复用统一边界校验。
- 弹层可能挤压窄屏；桌面锚定触发控件，窄屏改为底部面板并纵向排列输入。

- 测试请求记录 7 天保留、自定义边界、分页和固定预设兼容性。
- 测试两处前端参数生成、范围校验、状态恢复和弹层交互。
- 运行完整 Python、Node 测试、JavaScript 语法、Python compileall 和 diff 检查。
- 人工重启后验证两页自定义时间弹层、刷新、分页、移动端布局和范围提示。

## 实际改动

- `local_proxy/core.py` 与 `local_proxy/server.py` 为两套控制接口增加自定义毫秒时间边界，并将边界传入 Token 汇总、Token 历史和请求历史查询。
- 请求历史写入与读取清理周期延长为 7 天，增加近 7 天预设，并拒绝超出最近 7 天保留范围的自定义请求查询。
- `proxy_static/index.html`、`styles.css` 与 `app.js` 增加共享时间范围弹层、精确到秒的本地日期时间输入、独立偏好保存、范围提示和完整关闭交互。
- 增加存储边界、7 天约束和前端时间控件测试，并同步静态资源版本断言。

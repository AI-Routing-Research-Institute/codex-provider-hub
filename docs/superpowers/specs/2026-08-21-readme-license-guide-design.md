# README 使用教程与双许可证设计

## 目标

让第一次接触 Codex Provider Hub 的用户仅阅读 README 就能判断项目是否适合自己，并完成下载安装、CC Switch 供应商导入、Codex/Claude Code 接入、供应商切换和常见问题排查。同时采用 `AGPL-3.0-or-later + 商业许可证` 双许可证模式，为公开源码使用和闭源商业使用提供清晰边界。

## 目标用户

- 已经使用或准备使用 CC Switch 管理多个 Codex、Claude Code API 供应商的个人开发者和小团队。
- 希望 Codex 与 Claude Code 共用一个本地程序、分别切换供应商，并保留重试、请求记录、Token 统计和远程监控能力的用户。
- 遇到部分中转需要 `curl_cffi` 兼容传输，但不希望全部供应商改变网络行为的用户。

README 同时明确项目不提供 API Key、不代理售卖供应商服务，也不是面向公网多租户部署的网关。没有任何供应商配置的用户需要先在 CC Switch 或本工具的本地供应商管理界面中添加配置。

## README 信息架构

README 按普通用户完成任务的顺序组织：

1. 项目定位、适用人群、平台和最新版本下载。
2. 五分钟快速开始：准备 CC Switch、启动程序、打开两个控制台、导入供应商。
3. 配置 Codex：从控制台复制配置片段、合并到 `~/.codex/config.toml`、重启一次 Codex。
4. 配置 Claude Code：从控制台复制环境配置，说明 `ANTHROPIC_BASE_URL` 不需要额外添加 `/v1`，本地占位 Key 不是上游 Key。
5. 日常操作：选择、搜索、排序、隐藏、新增、编辑和再次从 CC Switch 导入。
6. 兼容传输：默认 `httpx`；只对 Cloudflare 403 供应商选择 `curl_cffi`。
7. 重试、会话路由、Token 统计、服务器监控和供应商上传。
8. 常见问题与状态码边界。
9. macOS、源码运行、服务器监控部署、项目结构、测试和安全边界。
10. 开源与商业授权。

目录只保留上述主要章节，不为每个短小子步骤增加目录项。现有重复的源码运行编号会统一修正，过时的“持续只读 CC Switch 数据库”表述改为实际行为：首次启动把 CC Switch 供应商导入本地独立目录；之后用户可以在控制台再次执行“仅新增”或“覆盖已有”导入。

## CC Switch 使用关系

README 将 CC Switch 标记为推荐搭配，而不是无法替代的运行依赖：

- 推荐先在 CC Switch 中集中维护供应商和 Key。
- 首次启动在本地目录为空时执行一次初始化导入。
- 之后 Codex Provider Hub 使用自己的本地供应商目录，页面编辑不会反向修改 CC Switch。
- CC Switch 更新后，用户可以在供应商管理模式选择“仅新增”或“覆盖已有”再次导入。
- 用户也可以完全在本工具中新增供应商，但批量管理时仍推荐 CC Switch。

## 使用教程准确性

教程以当前统一端口 `17890` 为准：Codex 控制台为 `/control/codex/`，Claude Code 控制台为 `/control/claude/`。Codex 客户端连接 `/v1`；Claude Code 的 `ANTHROPIC_BASE_URL` 使用 `http://127.0.0.1:17890`，不手工追加 `/v1`。

供应商传输方式说明必须强调默认标准模式不会影响正常供应商。只有出现 Cloudflare HTML 403，并确认相同 Key 直接使用客户端正常时，才在“供应商 → 管理 → 编辑 → 请求传输方式”选择兼容模式。真实的 401、503 和模型无可用渠道继续由上游返回，不应描述为本地自动修复。

## 常见问题

README 提供可执行的排查顺序：

- Claude Code 显示 `Not logged in`：使用控制台复制的环境配置启动，确认 Base URL 指向本地端口，并设置非空本地占位认证值。
- HTTP 403 且正文为 Cloudflare HTML：只为该供应商启用 `curl_cffi`。
- HTTP 401：检查当前选择的供应商、Key 和自定义认证头，不把服务器监控成功等同于本地当前配置正确。
- HTTP 503：展示上游错误正文；“模型无可用渠道”属于供应商业务状态，不由本地切换传输解决。
- 页面打不开：检查托盘进程、`/healthz` 和端口占用，不通过结束所有同名进程的方式排查。
- 修改未生效：确认使用最新安装包、保存供应商编辑、必要时刷新页面；端口修改需要重启应用。

# 监控排序一致性与停用黑与白设计

## 目标

保持公开监控面板按健康度排序，同时让监控管理展示完全采用同一最终排序；管理页人工顺序只作为全不可用供应商之间的低优先级排序依据。停用“黑与白”的自动监控，保留手动检测能力和既有历史。

## 架构

- 状态服务继续由 `_sort_providers_by_model` 计算健康度排序。
- 管理列表通过受限 SSH 读取服务器配置顺序，并读取公开状态接口的最终顺序；公开状态不可用时回退配置顺序。
- 服务器 `.order.json` 保存人工顺序。排序键先按健康度排序，再仅对聚合状态为 `down` 的供应商按人工顺序稳定排序。
- 新增受限管理动作，将指定供应商切换为 `manual_only`，重启 Worker 并在失败时恢复配置。

## 行为与边界

- 健康度优先级和既有成功次数/最近成功时间规则保持不变。
- 管理页上移/下移保存后，公开面板中全不可用供应商的相对顺序随之改变；其他状态供应商不受人工顺序覆盖。
- “黑与白”改为 `probe_mode = "manual_only"`，自动队列和自动历史新增停止；凭据、显示模型、历史数据不删除。

## 错误处理与测试

- 状态接口错误时管理页回退配置顺序并显示提示；停用动作验证 id、原子写入并在重启失败时回滚。
- 覆盖健康排序、down tie-breaker、管理/公开顺序一致性、停用动作及 Worker 无自动目标。
